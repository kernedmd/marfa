## 3. Доктрина ролей — кортикальная модель

Резолюции Создателя от 17.11.2026:

- **Р-1. 3B никогда не обучает 30B.** Где встречается — вычищено (см. правки, раздел 7.4).
- **Р-2. 30B — префронтальная кора (Мозг).** Решения, планы, речь. Не тратит ресурсы
  на «разглядывание пикселей» — получает от глаз готовый структурированный текст.
- **Р-3. 3B — зрительная кора (Глаза).** Только распознавание образов, текста
  и координат на экране. Быстрая, живёт на видеокарте, минимум энергии.
- **Р-4. Для ориентации в интерфейсах — мультимодальная модель (VLM), не «голый» OCR:**
  VLM возвращает и текст, и координаты (bounding boxes).

| | Мозг (префронтальная кора) | Глаза (зрительная кора) |
|---|---|---|
| Модель | Qwen3-30B-A3B, Q4_K_M | Qwen2.5-VL-3B-Instruct, Q4_K_M + mmproj |
| Ресурсы | CPU + ~20 ГБ RAM, `--mlock` | VRAM ~4,5 ГБ, `-ngl 99` |
| Порт | 8082 | 8083 |
| Сэмплинг | по терапии Этапа 2 (раздел 5) | temp 0.1, top_p 0.8, top_k 20 — сенсор, не собеседник |
| Вопрос | «ЧТО ДЕЛАТЬ?» | «ЧТО на экране и ГДЕ оно?» |
| Выход | речь, планы, решения | JSON-дескриптор экрана |
| Никогда | не смотрит на пиксели | не решает, не ведёт беседу, не интерпретирует намерения |

**Fallback-цепочка мозга:** 30B → GigaChat → **дежурный режим** (рекомендация
архитектора): Марфа перестаёт решать задачи, глаза продолжают смотреть и писать
лог; после восстановления — доклад «что было на экране». Альтернатива — 3B в
текстовом режиме как третья ступень — на решение Создателя (раздел 11).

## 5. Здоровье мозга (фоновая дорожка — лечим по ходу стройки)

Симптомы: выдуманные факты, языковая каша, обрывки thinking-тегов.

| № | Гипотеза | Проверка | Лечение |
|---|---|---|---|
| 1 | Q4_K_M деградирует на MoE (факты, русский) | A/B: батарея на Q4 и Q6 | переход на Q6_K |
| 2 | Сэмплинг вне рекомендаций Qwen3 | сверка флагов llama-server | без thinking: temp 0.7, top_p 0.8; с thinking: 0.6, 0.95; top_k 20, repeat_penalty 1.0 |
| 3 | Thinking-режим: обрывки тегов | батарея помечает; логи | поддержка `reasoning_content` либо отключение |
| 4 | ctx 4096: хвост вытесняет SYSTEM | логи, длина промпта | ctx 8192; иерархия №51/№60: ЯДРО не режется |
| 5 | Персона/RAG без заземления | сравнение сырой мозг (8082) vs конвейер (5001) | «не знаешь — скажи»; данные в рамках-тегах «данные, не истина»; биография отдельно от знаний |

**Батарея:** 15 вопросов (13 фактических F01–F13 + 2 ловушки честности H01–H02,
правильный ответ «не знаю»). Четыре прогона: `q4km-default`, `q4km-fix`,
`q6km-default`, `q6km-fix`. Ось изоляции: те же вопросы напрямую в 8082 и через
панель 5001 — врёт сырой мозг (квант/сэмплинг/шаблон) или конвейер (персона/RAG/обрезка).
Скрипт: `scripts\brain_battery.py`, чистый stdlib, JSON-логи в `logs/`.

**Критерии здоровья (вердикт Этапа 2):**

| Критерий | Порог |
|---|---|
| Ошибки фактов | ≤ 2 из 13 |
| Речевые сбои (каша, обрывки тегов) | 0 из 15 |
| Ловушки честности | 2 из 2 «не знаю» |
| Замедление Q6_K к Q4_K_M | < 2× (порог NO GO) |
| RAM (Ф97) | < 85% |

**Развилка квантизации:** q4km-fix проходит критерии — остаёмся на Q4_K_M.
Нет, а q6km-fix проходит и <2× — переходим на Q6_K. Q6 ≥2× медленнее — остаёмся
на Q4 и лечим заземлением (гипотезы 3–5). Врёт и Q6 — проблема не в кванте:
аудит `brain.py` по коду из bundle, копаем конвейер.

**Принцип гейта (бэклог):** до вердикта в доме не включается ничего, где
галлюцинирующий мозг производит «истину», которая остаётся в системе: кэш
ответов (№6), мутации промпта (№21, №22), синтетика (№27), авто-извлечение
фактов (№11), LLM-дайджесты и рефлексии (№43, №71–73, №78–79). Иначе лечить
придётся отравленную память.

## 6. Глаза (текущий фокус стройки)

Слоистые сенсоры — VLM не единственные глаза, а универсальный верхний слой:

| Слой | Источник | Что даёт | Цена |
|---|---|---|---|
| 0 | Заголовок и процесс окна (WinAPI) | «где я сейчас» | ~0 мс |
| 1 | Браузер: Playwright/CDP → DOM | точный текст, роли, координаты | бесплатно |
| 2 | Рабочий стол: UI Automation | деревья элементов win32/UWP | дёшево |
| 3 | **Глаза VLM (Дорожка Г)** | всё: canvas, картинки, игры, сканы | 2–6 с на снимок |

Правило слияния: элемент виден в DOM/UIA — истина оттуда; VLM отвечает за то,
чего там нет. Мозг видит только JSON-дескриптор, никогда пиксели. Элементы с
confidence < 0.6 мозг обязан считать НЕИЗВЕСТНЫМИ.

Правила честных глаз: temp 0.1; запрет выдумывать элементы («лучше пустой
список, чем выдуманная кнопка»); замкнутый цикл «действие → снимок → проверка
изменения; не изменилось — стоп и вопрос Илье»; глаза не интерпретируют —
только факты.

План Дорожки Г:

| Шаг | Что | Критерий |
|---|---|---|
| Г-1 | PoC: запуск 8083 при живом мозге, `vision_smoke.py` | оба живы; 30B медленнее ≤15%; VRAM ≤5,3 ГБ; JSON ≤8 с; центр bbox ±40 px; выдуманных элементов 0 |
| Г-2 | Батарея честности глаз V01–V05 (несуществующие кнопки) | правильный ответ «не вижу» |
| Г-3 | Интеграция: `sensors/vision/` (capture, vlm_client, fusion, calibrate) | зелёные тесты + коммит |
| Г-4 | Слои 1–2: DOM и UIA, подсказка глазам из DOM | меньше галлюцинаций, короче ответ |

Детали: `ТЗ_Глаза_v1.md` (модель, команды запуска, скрипт, риски и планы Б).

Честные риски прогнозов:

- Q6_K ≥2× медленнее → остаёмся на Q4_K_M + заземление (перенос вехи терапии не критичен).
- Оба кванта врут → проблема в конвейере: аудит `brain.py`; веха v10 сдвигается на глубину аудита.
- VLM не влезает в VRAM (драйвер прожорливее) → mmproj Q4_K, ctx 4096 либо Qwen2-VL-2B (план Б из ТЗ Глаз).
- Координаты плывут из-за DPI → `calibrate.py` + failsafe; клики только после валидации центра bbox.
- Мелкий русский текст не читается → ширина снимка 1920 вместо 1600 (медленнее, но читабельно).
