# Установка дома Марфа на чистой Z440 (ТЗ Раздел 9)

Цель: чистая Windows 10/11 x64 → рабочий дом `C:\Marfa` за один прогон.
Каждый шаг ставит своё, проверяет себя, пишет маркер `data\install_state\<шаг>.done` и
журнал `logs\install_<шаг>.log` (источник правды, 6.6). Провал шага останавливает конвейер;
повторный запуск пропускает уже сделанное.

## Перед стартом

- Windows 10/11 x64, пользователь с правами администратора.
- Свободно **≥ 90 ГБ** на диске: мозг 18.63 + опц. Q6_K 25.10 + студент ~7 + venv/кэши ~10 + запас.
- Интернет (для скачивания; мозг после установки работает офлайн).
- Репозиторий уже в доме: `git clone https://github.com/kernedmd/marfa C:\Marfa` (или перенос с помощью `docs/GITHUB_PUSH.md`).

## Прогон

```bat
cd C:\Marfa
scripts\00_install_all.bat
```

Конвейер:

| Шаг | Скрипт | Что делает | Проверка |
|---|---|---|---|
| 1 | `01_install_python.bat` | Python 3.11.9 тихо в `python311\`; если 3.11.x уже стоит на машине — шаг подключит его без переустановки | `python --version` = 3.11.x, pip, venv |
| 2 | `02_install_llamacpp.bat` | llama.cpp AVX2 с GitHub Releases (+ MSVC Redist) | `llama-server.exe --version` |
| 3a | `03a_download_model_q4km.bat` | мозг Q4_K_M 18.63 ГБ (официальный HF, докачка) | размер в допуске + SHA-256 в лог |
| 3b | `03b_download_model_q6k.bat` | опция Q6_K 25.10 ГБ — **вне конвейера**, по решению Ильи (Раздел 8) | размер + SHA-256 |
| 4 | `04_install_qlora.bat` | venv, torch cu118 (Pascal), bitsandbytes NF4, peft/trl, студент Qwen2.5-3B | импорт стека, CUDA, GTX 1060 |
| 5 | `verify.bat` | сводный аудит дома | версии, RAM 44/64, VRAM 6 ГБ, порты, .env вне git, selftest |
| 6 | `smoke_test.bat` | мозг: старт → фиксированный промпт → ток/с → стоп | ответ получен, ток/с в лог |

## После установки

```bat
scripts\start_llama_server.bat          :: мозг 8082 (Q4_K_M по умолчанию; Q6_K — аргументом)
scripts\start_marfa.bat                 :: панель web на 5001 (5000 не трогаем — 6.4)
scripts\run_tests.bat                   :: pytest всего дома (офлайн)
```

Смена кванта — Раздел 8 ТЗ: решение принимает Илья по итогам недели логов (правило 6).

## Частые причины провала

| Симптом | Причина | Что делать |
|---|---|---|
| `llama-server --version` молчит | нет MSVC Redistributable 2022 | шаг 02 ставит сам; при повторе — вручную `https://aka.ms/vs/17/release/vc_redist.x64.exe` |
| размер GGUF вне допуска | обрыв связи | удалить битый файл, повторить шаг 03a — докачка продолжится |
| `CUDA недоступна` | старый драйвер NVIDIA | обновить драйвер (GTX 1060 поддерживается cu118) |
| порт 8082 занят | мозг уже запущен | смоук-тест не стартует второй экземпляр — это нормально |
| `--mlock` не сработал | RAM занята посторонним | закрыть лишнее: план 44 из 64 ГБ — 0.1 |
| скачивание падает (curl, сеть) | python.org / GitHub / HF недоступны из вашей сети | скачать файл вручную в `C:\Marfa\downloads\` и перезапустить шаг — скрипт подхватит; источники печатает сам скрипт |
| `SHA-256 не совпал` | файл битый или скачан не тот | удалить файл из `downloads\`, повторить шаг |
| `'git' не является внутренней или внешней командой` | git на машине нет — дом работает и без него | для пуша в GitHub: `scripts\05_install_git.bat` (портативный git в `C:\Marfa\tools\git`) |
| `python.exe не появился в python311\` | Python 3.11.9 уже стоит на машине — тихий инсталлятор молча выходит 0 за секунды (TargetDir игнорируется) | ничего делать не нужно: шаг 01 сам находит установленный Python 3.11.x (реестр + типовые папки) и подключает его — путь в `data\python_path.txt`; диагностика в `logs\install_01_python.log` |
| `pip не отвечает` (шаг 01, адоптированный Python) | pip не установлен или окружение отравлено PYTHONHOME/PYTHONPATH от чужих установок | шаг 01 чинит сам: убирает вредные переменные и ставит pip через ensurepip (без сети); если не помогло — переустановить Python двойным кликом ('Install Now'), python-3.11.9-amd64.exe уже в downloads\ |
| шаг «умирает молча» в журнале (нет ни ПРОВАЛ, ни успеха) | висел системный диалог (vcruntime140/SmartScreen) при запуске exe; ошибка уходила только на экран | исправлено 12.11: vc_redist ставится до первого запуска llama-server, exe разблокируется, проверки с таймаутом, trap пишет любую ошибку в `logs\install_<шаг>.log` |

## Ничего вне дома (2.3)

Python, venv, llama.cpp, модели — всё внутри `C:\Marfa`. Установка в Program Files
и системные пути запрещена. `.env`, модели, venv, logs, data в git не попадают (2.4).

## РУЧНОЙ РЕЖИМ: «всё руками» (штатный путь с 12.11.2026)

Если сеть не пускает python.org / GitHub / Hugging Face — это не авария, а рабочий
режим. Светофор `scripts\90_manual_check.bat` ничего не качает и не ставит: он
показывает, что уже есть в доме, а для каждой недостающей позиции печатает точную
ссылку, имя файла и место, куда его положить. Уже скачанное конвейер подхватывает сам.

Порядок:

1. `scripts\90_manual_check.bat` — светофор: смотрите позиции с `[НЕТ]`.
2. Скачайте недостающее браузером (ссылки печатает светофор) и сделайте по таблице:

| Компонент | Что делать | Замечание |
|---|---|---|
| Python 3.11.9 | инсталлятор двойным кликом | если Python 3.11 уже стоит — ничего не нужно: шаг 01 подключит его сам |
| `vc_redist.x64.exe` | инсталлятор двойным кликом | https://aka.ms/vs/17/release/vc_redist.x64.exe |
| `llama-<версия>-bin-win-cpu-x64.zip` | положить в `C:\Marfa\downloads\` | имя не переименовывать; шаг 02 распакует сам |
| `Qwen3-30B-A3B-Q4_K_M.gguf` (~18.63 ГБ) | положить в `C:\Marfa\models\` | имя должно совпасть точно; недокачанный файл шаг 03a докачает |
| студент Qwen2.5-3B-Instruct | положить в `C:\Marfa\models\Qwen2.5-3B-Instruct\` | только если шаг 04 не дотянул HF сам (список файлов печатает шаг) |

3. Снова `scripts\90_manual_check.bat` — пока есть `[НЕТ]`, повторяйте шаг 2.
4. Когда `[НЕТ]` не осталось: `scripts\00_install_all.bat`. Готовые шаги пропустятся
   по маркерам `data\install_state\*.done`, остальное доустановится: venv, pip-пакеты
   (при провале pypi.org pip сам повторяет через зеркало), llama.cpp распакуется,
   модели проверятся по размеру. Сеть нужна только pip-пакетам; если и тут блокировки —
   зеркала включены, а при полном провале журнал подскажет ручной путь.

Если шаг всё же упал — журнал `logs\install_<шаг>.log` содержит причину и диагностику;
исправьте и перезапустите `00_install_all.bat`: конвейер продолжится с места провала.
