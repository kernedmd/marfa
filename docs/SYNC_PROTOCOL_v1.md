  раздела 4а включается отдельной резолюцией Создателя).

## 4. Почему bundle, а не прямой доступ станции к GitHub

Приватный репозиторий требует авторизации. Единственный способ дать станции доступ —
передать токен, а это запрещено Ф105 и гигиеной 2.4 (токен в чат — никогда).
Bundle решает задачу без секретов: он содержит всю git-историю, проверяется
(`git bundle verify`), мерджится как обычный remote и едет через чат как обычный файл.

## 4а. Прямой забор из GitHub (опция, с 17.11.2026)

Когда у сервера архитектора есть СВОЙ токен, пересылка bundle через чат не нужна:
`server_sync.py` v1.2 сам забирает историю из GitHub (шаг 0 петли).

Как включить (Создатель делает руками на сервере; Ф105 — токен не через чат):

1. GitHub → Settings → Developer settings → Fine-grained personal access tokens →
   новый токен: только репозиторий `marfa`, право **Contents: Read-only**,
   минимальный срок действия.
2. На сервере рядом с рабочей копией создать `.env` (файл в .gitignore):

       MARFA_GH_TOKEN=github_pat_...
       MARFA_GH_REPO=kernedmd/marfa   :: необязательно, это значение по умолчанию

3. Дальше как всегда: `python3 scripts/server_sync.py`.

Гарантии: токен не печатается и не пишется в `.git/config` — живёт только в
`.env` сервера; весь вывод git маскируется звёздочками; интерактивные запросы
пароля отключены (скрипт не зависает); без `.env` канал молча выключен и
станция работает по bundle, как раньше.

Пуш коммитов станции в GitHub — отдельная опция `MARFA_GH_PUSH=1` в том же
`.env`. По умолчанию ВЫКЛЮЧЕН (канон: пуш делает только Создатель со своей
машины). Включается только явной резолюцией Создателя в журнале MASTER_TZ.

Если Создатель решит сделать репозиторий публичным, прямой забор работает
и без токена: `git fetch https://github.com/kernedmd/marfa.git main`.
Цена — код дома становится виден миру; решение фиксируется резолюцией
в MASTER_TZ (раздел 7).

## 5. Память архитектора — docs/ARCHITECT_LOG.md

Журнал живёт в репозитории и путешествует по всем трём берегам. Каждая синхронизация
дописывает запись: дата, HEAD, что забрано, результаты тестов. Контекст ИИ-сессий
теряется — файлы станции остаются; ARCHITECT_LOG — механизм «помнить» для архитектора.
Правило записи: факты и цифры, без воды; каждая запись датирована.

## 6. Первое подключение дома (разовый вход в петлю, 19.11.2026)

Кнопка не может приехать через кнопку: `80_sync_github.bat` доставляется в дом
через чат архитектора — один раз, руками Создателя (git на Z440 уже стоит, шаг 05):

1. Скачать из чата два файла: свежий bundle станции (`marfa-station-*.bundle`)
   и саму кнопку `80_sync_github.bat`.
2. Разложить: bundle → `C:\Marfa\incoming\` (папку создать), кнопка →
   `C:\Marfa\scripts\`.
3. Запустить `scripts\80_sync_github.bat`. Кнопка сама: создаст репозиторий
   (git init + снимок дома без рантайма), вольёт историю GitHub (нет прав —
   предупредит и продолжит), примет ВСЕ bundle архитектора из incoming\
   (новейший первым; старые, уже вросшие в историю, — за секунду), прогонит
   чистку дома (наследие v9.3 → _trash\), закоммитит, попробует пушить
   GitHub и соберёт ответный bundle. Провал пуша петлю не останавливает.
4. Файл из `C:\Marfa\outgoing\marfa-*.bundle` отправить архитектору в чат.
   Петля замкнулась: дальше обе стороны живут по разделу 2.

Замена кнопки руками больше не нужна НИКОГДА (v3.2, 20.11.2026). Кнопка
работает с временной копии; если слияние принесло новую её версию — прогон
перезапускается новой версией сам (шаг 3z). Исключение — только уже
установленная v3.0/v3.1: у них шага 3z нет, поэтому первое обновление до
v3.2 требует два нажатия подряд (первое приносит кнопку в дерево, второе
её исполняет). Дальше — всегда одно нажатие на цикл.

## 7. Открытая возможность (на резолюцию Создателя)

«Пульс станции»: ежедневное срабатывание архитектора по расписанию (проверка станции,
прогон тестов, короткий доклад Создателю). Включается только явной резолюцией —
вопрос №6 к MASTER_TZ.

## 8. Один источник правды и анти-мусор (v1.2, 19.11.2026)

Урок от 19.11.2026: станция накопила в download/ дубли — 10 точных копий
файлов репо (доки и скрипты), __pycache__, файл с Windows-путём в имени,
устаревшие PDF/DOCX-рендеры документов и старый bundle. Создатель назвал
это мусором и прав: у файла должно быть одно имя, одно место, одна история.

Правила:

1. Рабочая копия репозитория — единственное место, где живут и меняются
   файлы проекта (Z440: `C:\Marfa`; станция: рабочая копия `marfa/`).
   Новая работа = коммит в репо, а не файл в download/.
2. download/ станции содержит ТОЛЬКО исходящий bundle для Создателя
   (плюс файлы, которые Создатель явно попросил выложить в чат — они
   удаляются сразу после выдачи).
3. Копировать файлы репо в download/ «для удобства» запрещено — это и есть
   мусор. Канон версии — git-история, а не папка выдачи.
4. Новые файлы приходят на станцию только через upload/ (bundle, zip,
   одиночные файлы): после приёма они коммитятся в репо, копий не плодится.
5. server_sync.py v1.3, шаг [4]: блоб каждого файла download/ (кроме
   *.bundle) сверяется с базой объектов репозитория — точные дубли помечаются,
   с `--clean-download` удаляются. Bundle не трогается никогда.
6. Документ живёт в docs/ как .md. PDF/DOCX-рендеры не хранятся: делаются
   по запросу Создателя и удаляются после выдачи.
