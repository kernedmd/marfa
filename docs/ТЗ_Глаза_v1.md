## 0. Резолюция Создателя (канон)

1. **3B НИКОГДА не обучает 30B.** Если где-то в проекте это написано — удалить.
2. **30B — Префронтальная кора (Мозг).** Принимает решения, строит планы, общается. Не тратит ресурсы на «разглядывание пикселей» — получает от глаз готовый структурированный текст.
3. **3B — Зрительная кора (Глаза).** Только распознавание образов, текста и координат на экране. Быстрая, живёт на видеокарте (6 ГБ VRAM), потребляет минимум энергии.
4. Для ориентации в интерфейсах используется **мультимодальная модель (VLM)**, а не «голый» OCR: VLM возвращает и текст, и координаты объектов (bounding boxes).

## 2. Доктрина ролей

| | Префронтальная кора (мозг) | Зрительная кора (глаза) |
|---|---|---|
| Модель | Qwen3-30B-A3B, Q4_K_M | Qwen2.5-VL-3B-Instruct, Q4_K_M |
| Где живёт | CPU (8 ядер) + ~20 ГБ RAM, --mlock | GPU (6 ГБ VRAM, -ngl 99) |
| Порт | 8082 | 8083 |
| Температура | по текущим настройкам мозга | 0.1 — сенсор, а не собеседник |
| Отвечает на вопрос | «ЧТО ДЕЛАТЬ?» | «ЧТО на экране и ГДЕ оно?» |
| Формат выхода | речь, планы, решения | JSON-дескриптор экрана |
| Никогда | не смотрит на пиксели | не принимает решений, не ведёт беседу |

Ключевое следствие: глазам запрещено генерировать свободный текст для пользователя — только дескриптор. Мозг никогда не видит сырые пиксели, только структурированный текст от глаз.

## 3. Выбор модели глаз

| Кандидат | Q4_K_M + mmproj (примерно) | Комментарий |
|---|---|---|
| **Qwen2.5-VL-3B — рекомендация** | ~2.3 ГБ + ~0.7 ГБ | Зрелая, официально поддержана llama.cpp (репозиторий ggml-org), сильный OCR и заземление координат |
| Qwen3-VL-2B | ~1.7 ГБ + ~0.6 ГБ | То же поколение, что и мозг; легче; кандидат на A/B после Г-1 |
| Qwen2-VL-2B — план Б | ~1.6 ГБ + ~0.6 ГБ | Если VRAM окажется впритык |

Почему Qwen2.5-VL-3B, а не Qwen2-VL-2B:

1. **Координаты.** Поколение 2.5 обучено возвращать bounding boxes и заточено под агентные GUI-сценарии — ровно наш случай «кнопка "Отправить": X 450, Y 600».
2. **OCR.** 2.5 заметно лучше читает мелкий текст, включая русский.
3. **Скорость.** Window attention в визуальном кодировщике — быстрее на широких снимках экрана.
4. **Влезает.** Бюджет VRAM ниже — около 4.5 ГБ из 6 с запасом.

Семейство глаз НЕ обязано совпадать с семейством мозга: спекулятивный декодинг и дистилляция отменены (раздел 1), совместимость токенизаторов больше не требуется. Выбираем чисто по качеству зрения на 6 ГБ VRAM.

## 4. Бюджет ресурсов и принцип хозяина ресурса

Прежнее правило «последовательной выгрузки» (30B занимает всё — параллель запрещена) заменяется **принципом хозяина ресурса**:

- CPU + RAM — один хозяин: мозг (30B).
- VRAM — один хозяин: глаза (VLM).
- Разные ресурсы — **параллель разрешена**: пока 30B думает, глаза смотрят.
- Два CPU-LMM одновременно по-прежнему запрещены (старое правило сохраняется для CPU).

VRAM-бюджет GTX 1060 6 ГБ:

| Компонент | VRAM |
|---|---|
| Windows + DWM (карта дисплейная) | ~1.0 ГБ |
| Qwen2.5-VL-3B, LLM-часть Q4_K_M | ~2.3 ГБ |
| mmproj (визуальный кодировщик) Q8_0 | ~0.7 ГБ |
| KV-кэш 8K + вычислительные буферы | ~0.4–0.6 ГБ |
| **Итого** | **~4.4–4.6 ГБ из 6** |

(точные размеры файлов подтверждаем после скачивания на Г-1; запас ~1.4 ГБ)

Прочее:

- RAM: глаза добавляют ~1 ГБ системной памяти (буферы хоста) — незаметно на фоне 64 ГБ.
- CPU: при полном офлоаде (-ngl 99) глаза почти не трогают CPU; потоков даём 2. Ожидаемая деградация скорости 30B при работе глаз — до 5–10%.
- Скорость глаз (прогноз, измерим на Г-1): снимок шириной 1600 px → JSON за 2–6 с.

## 5. Слоистые сенсоры (предложение сверх базовой схемы)

VLM — не единственные глаза, а верхний универсальный слой. DOM и UI Automation точнее и бесплатнее, когда доступны. Глаза VLM — для всего, что не отдаётся структурированно: canvas, игры, картинки, сканы, нестандартные интерфейсы, вебкам.

| Слой | Источник | Что даёт | Цена |
|---|---|---|---|
| 0 | Заголовок и процесс активного окна (WinAPI) | «где я сейчас» | ~0 мс |
| 1 | Браузер: Playwright/CDP → DOM + accessibility | точный текст, роли, координаты | бесплатно |
| 2 | Рабочий стол: Windows UI Automation (pywinauto) | деревья элементов win32/UWP | дёшево |
| 3 | Глаза VLM (это ТЗ) | всё остальное + уточнение слоёв 1–2 | 2–6 с на снимок |

Правило слияния (sensor fusion): если элемент виден в DOM/UIA — истина оттуда; VLM отвечает за то, чего там нет (иконки, canvas, безымянные кнопки, картинки). Глазам можно передавать подсказку из DOM — меньше галлюцинаций, короче ответ.

Порядок внедрения: сначала слой 3 (ядро этого ТЗ, работает везде), слои 1–2 подключаем по мере роста задач (web-модуль уже есть — слой 1 будет первым).

## 6. Протокол «Экранный дескриптор»

Глаза возвращают строго JSON. Имена полей английские (стабильность парсинга), значения — как на экране.

```json
{
  "active_window": "Блокнот",
  "screen_size": [1920, 1080],
  "elements": [
    {"type": "button", "text": "Отправить", "bbox": [412, 580, 488, 612], "confidence": 0.93},
    {"type": "input", "text": "Поиск...", "bbox": [20, 8, 300, 36], "confidence": 0.88}
  ],
  "summary": "Диалог отправки письма, фокус в поле поиска"
}
```

- type: button | input | link | menu | text | icon | image
- bbox: [x1, y1, x2, y2] в пикселях продескейленного снимка
- confidence: 0–1

### 6.1. Грамматика: JSON по принуждению (совет Создателя №1)

Промпт «выдай строго JSON» — это просьба; грамматика — это закон. llama-server умеет
превращать JSON-схему в GBNF-грамматику, и тогда модель **физически не может** сгенерировать
ни одного токена вне схемы: ни markdown-заборы ```` ```json ````, ни «Вот JSON:», ни пояснений.

Основной путь — **per-request `response_format`** в теле каждого запроса (его шлёт vlm_client):

```json
"response_format": {
  "type": "json_schema",
  "json_schema": {"name": "screen_descriptor", "schema": { ... }}
}
```

- Схема — только каркас (required: elements, bbox из 4 целых); без лишних ограничений,
  чтобы не душить качество 3B-модели.
- Работает без перезапуска сервера и не мешает другим запросам (глазам будут задаваться
  и короткие да/нет-вопросы с другими схемами).
- Если сборка сервера не знает response_format — поле игнорируется, и работает
  парсер-фолбэк (срез ```-заборов) из скрипта. Скрипт печатает, принят ли response_format.

Тяжёлая альтернатива — флаги сервера при старте (`--grammar <файл.gbnf>` или
`--json-schema`): жёстко, но действует на ВСЕ запросы этого сервера, включая будущие
да/нет-вопросы. Поэтому не основной путь; в Г-3, когда дескриптор станет единственным
форматом выхода глаз, можно перевести на `--grammar` и убрать из запросов.

### 6.2. Координаты и калибровка (совет Создателя №2)

Здесь живут ДВЕ независимые проблемы, обе закрываем:

1. **Пространство снимка ≠ физический экран.** Снимок масштабируется до 1600 px;
   координаты VLM — в пространстве снимка. Исполнитель действий умножает на коэффициент
   (физическая_ширина / 1600). Скрипт печатает коэффициенты по обеим осям.
2. **DPI-виртуализация Windows.** При масштабе 125%/150% не-DPI-aware процесс получает
   от мыши логические координаты, а не физические — pyautogui нажмёт мимо. Решение:
   каждый процесс-сенсор на старте вызывает `SetProcessDpiAwareness(2)` (per-monitor
   aware) — тогда и mss, и pyautogui говорят в физических пикселях. Зашито в скрипт v1.1;
   в Г-3 переезжает в calibrate.py.

Тест «Пуск» (встроен в vision_smoke.py v1.1):

- Свежий снимок → сфокусированный вопрос «найди кнопку Пуск, верни bbox».
- Центр bbox пересчитывается в физические координаты → `pyautogui.moveTo` (failsafe=True,
  плавное наведение 0.6 с) → Илья визуально подтверждает: курсор на кнопке.
- С флагом `--click-start` — полный замкнутый цикл: клик → новый снимок → вопрос
  «открыто ли меню Пуск?» → Esc (закрыть меню). Это мини-репетиция правила «действие →
  снимок → проверка» из раздела 6.4.
- Клик только по валидированному центру bbox; мышь в угол экрана = аварийный стоп
  (FAILSAFE pyautogui).

Отдельный модуль calibrate.py (Г-3) наследует: DPI-awareness, пересчёт пространств,
валидацию bbox перед кликом, эталонную сетку для регрессионной проверки.

### 6.3. Как мозг получает дескриптор

- В системный промпт 30B добавляется блок: «ЭКРАН (снимок N сек назад): {дескриптор}».
- Элементы с confidence < 0.6 мозг обязан считать НЕИЗВЕСТНЫМИ, а не существующими.
- Дескриптор не вытесняет ЯДРО системного промпта (правило «ЯДРО не режется + бюджет»
  из списка 100, п.51/60).

### 6.4. Правила честных глаз (анти-галлюцинации)

1. temp 0.1, top_p 0.8, top_k 20 — сенсор должен быть почти детерминированным.
2. Грамматика JSON (6.1) + запрет в промпте: «Не выдумывай элементы. Нечитаемое —
   confidence < 0.4. Лучше пустой список, чем выдуманная кнопка».
3. Замкнутый цикл: после каждого действия — новый снимок и подтверждение, что состояние
   экрана изменилось. Не изменилось — стоп и вопрос Илье.
4. Глаза не интерпретируют намерения («пользователь раздражён») — только факты.
   Интерпретация — работа мозга.

## 7. Fallback-цепочка мозга (правка списка 100)

Прежнее: 30B → GigaChat → 3B.

Рекомендация (чистая доктрина): **30B → GigaChat → дежурный режим.** Марфа перестаёт решать задачи, глаза продолжают смотреть и писать лог; при восстановлении мозга — короткий доклад «что происходило на экране, пока ты отдыхал».

Альтернатива (на решение Создателя): третьей ступенью — 3B-VLM в текстовом режиме. Технически возможна: LLM-часть у VLM полноценная. Но это исключение из доктрины ролей (глаза, которые вдруг думают). По умолчанию в ТЗ — чистая доктрина.

    --click-start    полный замкнутый цикл: клик по «Пуск» + проверка меню
Зависимости: venv\\Scripts\\pip install mss pyautogui

Совет №1 — JSON по грамматике: каждый запрос несёт response_format/json_schema;
если сборка сервера его не знает, поле игнорируется и работает парсер-фолбэк.
Совет №2 — DPI: процесс делается DPI-aware, снимок и мышь говорят в физических
пикселях; тест «Пуск» проверяет пересчёт координат снимка в физические.
Совет №3 — Pascal/ViT: если ответ дольше 8 с, тест сам повторяет проход на 1280.
"""
import argparse
import base64
import ctypes
import io
import json
import sys
import time

import requests
from PIL import Image

try:
    import mss
except ImportError:
    sys.exit("Нет модуля mss: venv\\Scripts\\pip install mss")

# --- DPI-awareness: физические пиксели для снимка И мыши (совет №2) --------
if sys.platform == "win32":
    try:
        ctypes.windll.shcore.SetProcessDpiAwareness(2)  # per-monitor aware
    except Exception:
        try:
            ctypes.windll.user32.SetProcessDPIAware()
        except Exception:
            pass

BRAIN = "http://127.0.0.1:8082"
EYES = "http://127.0.0.1:8083"

PROMPT = (
    "Ты — зрительный сенсор интерфейсов. Опиши экран строго одним JSON без пояснений:\n"
    '{"active_window":"...","elements":[{"type":"button|input|link|menu|text|icon|image",'
    '"text":"...","bbox":[x1,y1,x2,y2],"confidence":0.0}],"summary":"одно предложение"}\n'
    "Правила: bbox в пикселях входного изображения; не выдумывай элементы; "
    "нечитаемое — confidence меньше 0.4; лучше меньше элементов, чем выдуманные."
)

START_PROMPT = (
    "Найди на панели задач кнопку «Пуск» (левый нижний угол, логотип Windows). "
    "Ответь строго одним JSON без пояснений: "
    '{"found":true,"bbox":[x1,y1,x2,y2],"confidence":0.0}. '
    'Если кнопки не видно: {"found":false,"bbox":null,"confidence":0}. '
    "Координаты — в пикселях входного изображения. Не выдумывай."
)

MENU_PROMPT = (
    "Посмотри на экран. Открыто ли сейчас меню «Пуск» (панель со списком программ)? "
    'Ответь строго JSON: {"menu_open": true} или {"menu_open": false}.'
)

# --- Схема дескриптора для response_format (совет №1) ----------------------
SCHEMA = {
    "type": "object",
    "properties": {
        "active_window": {"type": "string"},
        "elements": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "type": {"type": "string"},
                    "text": {"type": "string"},
                    "bbox": {
                        "type": "array",
                        "items": {"type": "integer"},
                        "minItems": 4,
                        "maxItems": 4,
                    },
                    "confidence": {"type": "number"},
                },
                "required": ["type", "bbox"],
            },
        },
        "summary": {"type": "string"},
    },
    "required": ["elements"],
}


def health(url):
    try:
        return requests.get(url + "/health", timeout=5).status_code == 200
    except Exception:
        return False


def screenshot(width):
    with mss.mss() as sct:
        raw = sct.grab(sct.monitors[1])  # основной монитор, физические пиксели
        img = Image.frombytes("RGB", raw.size, raw.rgb)
    scale = width / img.width
    small = img.resize((width, round(img.height * scale)), Image.LANCZOS)
    buf = io.BytesIO()
    small.save(buf, format="PNG")
    b64 = base64.b64encode(buf.getvalue()).decode()
    return b64, img.size, small.size


def ask_eyes(b64, prompt, max_tokens=1500):
    """Запрос к глазам. Сначала с response_format/json_schema; если сервер
    отклонил (код >= 400) — повтор без грамматики, дальше парсер-фолбэк."""
    for use_schema in (True, False):
        body = {
            "model": "vlm",
            "temperature": 0.1,
            "top_p": 0.8,
            "max_tokens": max_tokens,
            "messages": [{
                "role": "user",
                "content": [
                    {"type": "image_url",
                     "image_url": {"url": "data:image/png;base64," + b64}},
                    {"type": "text", "text": prompt},
                ],
            }],
        }
        if use_schema:
            body["response_format"] = {
                "type": "json_schema",
                "json_schema": {"name": "screen_descriptor", "schema": SCHEMA},
            }
        r = requests.post(EYES + "/v1/chat/completions", json=body, timeout=240)
        if use_schema and r.status_code >= 400:
            print("  response_format отклонён сервером (код %s) — "
                  "повтор без грамматики" % r.status_code)
            continue
        r.raise_for_status()
        return r.json()["choices"][0]["message"]["content"], use_schema
    raise RuntimeError("глаза не ответили")


def parse_json(text):
    clean = text.strip()
    if clean.startswith("```"):
        clean = clean.strip("`").strip()
        if clean.startswith("json"):
            clean = clean[4:]
    return json.loads(clean)


def describe(width):
    """Один проход: снимок -> дескриптор. Возвращает метрики и данные."""
    t0 = time.time()
    b64, real, small = screenshot(width)
    t_shot = time.time() - t0
    t0 = time.time()
    out, schema_ok = ask_eyes(b64, PROMPT)
    t_ask = time.time() - t0
    try:
        data = parse_json(out)
        ok = "ВАЛИДНЫЙ" if isinstance(data.get("elements"), list) else "БЕЗ elements"
    except Exception as e:
        data, ok = None, "НЕВАЛИДНЫЙ (%s)" % e
    return dict(width=width, real=real, small=small, t_shot=t_shot, t_ask=t_ask,
                data=data, ok=ok, schema_ok=schema_ok, raw=out)


def calibrate_start(width, click=False):
    """Совет №2: DPI и координаты. Находим «Пуск», пересчитываем центр bbox
    в физические координаты, наводим мышь; с click=True — замкнутый цикл."""
    print("\n--- Калибровка «Пуск» (совет №2: DPI и координаты) ---")
    b64, real, small = screenshot(width)
    try:
        out, _ = ask_eyes(b64, START_PROMPT, max_tokens=100)
        d = parse_json(out)
    except Exception as e:
        print("калибровка: ответ не разобран (%s)" % e)
        return
    if not d.get("found"):
        print("Пуск не найден глазами — проверь панель задач вручную; "
              "для Г-1 не критично, но отметить")
        return
    bbox = d["bbox"]
    cx_v = (bbox[0] + bbox[2]) / 2.0
    cy_v = (bbox[1] + bbox[3]) / 2.0
    kx = real[0] / float(small[0])
    ky = real[1] / float(small[1])
    cx, cy = int(round(cx_v * kx)), int(round(cy_v * ky))
    print("bbox VLM: %s (пространство снимка %s)" % (bbox, small))
    print("центр: снимок (%d, %d) -> физические (%d, %d); коэффициенты %.3f / %.3f"
          % (cx_v, cy_v, cx, cy, kx, ky))
    try:
        import pyautogui
        pyautogui.FAILSAFE = True
    except ImportError:
        print("pyautogui нет — наведение мыши пропущено "
              "(venv\\Scripts\\pip install pyautogui)")
        return
    try:
        pyautogui.moveTo(cx, cy, duration=0.6)
    except Exception as e:
        print("moveTo не удался (%s) — проверь координаты вручную" % e)
        return
    print("мышь наведена на (%d, %d) — проверь глазами: курсор на кнопке «Пуск»?"
          % (cx, cy))
    if not click:
        print("полный цикл (клик + проверка меню): перезапусти с --click-start")
        return
    pyautogui.click()
    time.sleep(2.0)
    b642, real2, small2 = screenshot(width)
    try:
        out2, _ = ask_eyes(b642, MENU_PROMPT, max_tokens=50)
        print("глаза после клика:", parse_json(out2))
    except Exception:
        print("глаза после клика (сырой ответ):", out2[:200])
    pyautogui.press("esc")
    print("нажат Esc — меню закрыто (рабочий стол чист)")


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--width", type=int, default=1600,
                    help="ширина снимка для VLM: 1600 (умолчание), 1280, 1920")
    ap.add_argument("--click-start", action="store_true",
                    help="клик по «Пуск» + проверка меню (замкнутый цикл)")
    args = ap.parse_args()

    print("мозг 8082:", "жив" if health(BRAIN) else "НЕ ОТВЕЧАЕТ (продолжаем)")
    if not health(EYES):
        print("глаза 8083: НЕ ОТВЕЧАЮТ — остановка")
        sys.exit(1)
    print("глаза 8083: живы")

    r = describe(args.width)
    print("снимок: %s -> %s, %.2f с" % (r["real"], r["small"], r["t_shot"]))
    print("ответ глаз: %.1f с; response_format: %s"
          % (r["t_ask"],
             "принят сервером" if r["schema_ok"] else "НЕ принят (фолбэк-парсер)"))
    print("JSON:", r["ok"])
    if r["data"]:
        for el in r["data"].get("elements", [])[:12]:
            print("  ", el)
    else:
        print("СЫРОЙ ОТВЕТ:\n", r["raw"][:2000])

    # Совет №3: Pascal без тензорных ядер — если медленно, автоповтор на 1280
    if r["t_ask"] > 8 and args.width > 1280:
        print("\n--- Медленнее 8 с: автоповтор на ширине 1280 (план Б, совет №3) ---")
        r2 = describe(1280)
        print("1280: ответ %.1f с против %.1f с на %d; JSON: %s"
              % (r2["t_ask"], r["t_ask"], args.width, r2["ok"]))
        if r2["data"]:
            for el in r2["data"].get("elements", [])[:6]:
                print("  ", el)

    calibrate_start(args.width, click=args.click_start)

    print("\n--- Самопроверка по критериям Г-1 ---")
    print("JSON валиден: %s" % ("да" if r["data"] else "НЕТ"))
    print("время ответа <= 8 с: %s (%.1f с)"
          % ("да" if r["t_ask"] <= 8 else "НЕТ", r["t_ask"]))
    print("живость 30B, VRAM и RAM проверь вручную: критерии 1-4, nvidia-smi")


if __name__ == "__main__":
    main()
