## 4. Автомат: дом работает сам

Требование Создателя (20.11.2026): «всё, что мы делаем, запускается
автоматом». Включается ОДНОЙ кнопкой:

```
C:\Marfa\Автозапуск_Марфы.bat        (если попросит права — «Запуск от администратора»)
```

Она вписывает в планировщик Windows две задачи:

| Задача | Когда | Что делает |
|---|---|---|
| «Марфа» | при входе в Windows | Поднимает весь дом (та же `Старт_Марфа.bat`-логика) |
| «Марфа-синхронизация» | каждые 2 часа | `80_sync_github.bat /auto` — петля сама, без нажатий и без пауз |

Руками, без кнопки:

```
schtasks /Query /TN "Марфа"                          :: посмотреть, что вписано
schtasks /Query /TN "Марфа-синхронизация"
schtasks /Delete /TN "Марфа" /F                      :: выключить автомат
schtasks /Delete /TN "Марфа-синхронизация" /F
```

Что важно знать про автомат:

- **Дом сам себя лечит.** Автодоктор (расписание) каждые 5 минут
  осматривает дом: порты мозг/глаза/панель, сердца ушей и стремления,
  диск. Слуга, мёртвый ДВА осмотра подряд, поднимается сам — той же
  командой, что и при старте (start_marfa.json), не чаще раза в
  30 минут на слугу. Вылетела панель посреди дня — вернётся сама.
  Ручной вариант: кнопка `84_doctor.bat` или команда «доктор» в чате.
- **Дом помнит себя.** Каждый день в 23:30 — бэкап души (доктрина,
  память, дневники, разговоры, уроки) в `data\backup\`, 14 последних;
  старшие — в `_trash\backup_old\`. По команде: «сохрани себя» в чате.
- Проверить, что автомат вписан: `schtasks /Query /TN "Марфа"` и
  `schtasks /Query /TN "Марфа-синхронизация"`.
- Окно синхронизации будет мелькать раз в 2 часа — это нормально, так
  дом «дышит» петлёй. Кто мешает — перенеси на реже:
  `schtasks /Create /F /TN "Марфа-синхронизация" /TR "\"C:\Marfa\scripts\80_sync_github.bat\" /auto" /SC HOURLY /MO 6` (раз в 6 часов);
- Первая синхронизация от планировщика может спросить вход GitHub —
  войди как kernedmd, Windows запомнит навсегда;
- Автосинхронизация коммитит всё, что нашлось в доме, ПЕРЕД слиянием
  (шаг `:clean_tree`) — твой незакоммиченный труд не потеряется;
- Уши поднимаются вместе с домом и НЕ умирают без микрофона — просто
  ждут (см. раздел 7).

## 5. Петля синхронизации: как дом говорит с архитектором

```
   Z440 (дом)                GitHub                Станция (архитектор)
   ──────────                ──────                ────────────────────
   80_sync_github.bat  ───►  github.com/   ───►    server_sync.py
   (кнопка или /auto)        kernedmd/marfa        забирает сам, без токена
                                                       │ тесты 420+, правки
   incoming\ ◄── bundle в чат ◄──────────────────────┘
      │
      └─► 80_sync_github.bat вливает, пушит в GitHub, собирает ответ
```

Твоё участие свелось к: скачать bundle из чата → положить в
`C:\Marfa\incoming\` → (кнопка или автомат сделает остальное).

Правила петли:
- при конфликте слияния **архитектор сильнее** (и на доме, и на станции);
- bundle, который уже врос, кнопка удаляет из `incoming\` сама;
- если пуш в GitHub не прошёл — петля жива, просто сделай руками:
  `cd C:\Marfa && git push origin main` (см. раздел 9, урок 4);
- канон: станция не пушит в GitHub сама — пушит только дом.

## 7. Уши: как Марфа слышит имя

Двухступенчатая схема (как у коммерческих ассистентов):

1. **Сторож имени** — vosk-model-small-ru-0.22 (45 МБ, ~1% CPU): слушает
   вечно и ловит слово «Марфа» (+фонетика: «марва», «марфу» — допуск
   Левенштейна 1). Слова «март», «форма» — мимо. «марка» — осознанный
   ложный пуск (лучше лишняя расшифровка, чем проспать зов).
2. **Расшифровка** — whisper-turbo (1.5 ГБ) — включается ПОСЛЕ имени
   и разбирает саму фразу. *Мост до неё ещё не построен, но модель уже
   в арсенале (`ggml-large-v3-turbo.bin` — см. docs\АРСЕНАЛ_МОДЕЛЕЙ.md):
   после глаз №2-6 — главный кандидат.*

Уши живут как служба: поднимаются со стартом дома, пишут сердцебиение
в `data\ears_status.json`, панель показывает карточку «Уши».

| Статус на панели | Что значит | Что делать |
|---|---|---|
| слушают | ухо живо, микрофон есть | ничего, позови Марфу |
| ждут микрофон | микрофона нет/занят | воткни; служба сама проснётся ≤60 с |
| модель не найдена | модель легла криво | `scripts\85_fix_ears.bat` |
| нет sounddevice | не стоит обёртка микрофона | `C:\Marfa\venv\Scripts\python.exe -m pip install sounddevice` |
| служба не отвечает | служба ещё поднимается / упала | подожди минуту; нет — перезапусти дом |

Разовое демо (60 сек), чтобы увидеть слух своими глазами:

```
C:\Marfa\venv\Scripts\python.exe sensors\ears.py --demo 60
```

Позови Марфу вслух — на экране вспыхнет `[ИМЯ!]`.

**Мостик до микрофона**: Z440 — десктоп, устройства ввода может не быть
вовсе (`Error querying device -1`). Подойдёт любой микрофон или веб-камера
с микрофоном; после подключения проверь: Параметры → Система → Звук → Вход.

## 8. Стремление: как Марфа сама чего-то хочет (Круг Д, 21.11.2026)

Пятый слуга — служба стремления (`venv\Scripts\python.exe -m core.drive
--service`, поднимается стартом дома). Тик раз в минуту:

- **план дня** — в 08:00 собирается из очереди задач (`data\queue.json`);
- **вечерний дневник** — в 21:00 факты дня в `data\diary\` (или скажи в
  чате «подведи день» — соберёт сразу);
- **вопросы** — каждую минуту Марфа смотрит, чего ей не хватает знать:
  задача висит неделю, уши молчат сутки, мозг молчит 2 часа — вопрос
  копится в `data\questions.json` и показывается на панели;
- **чтение** — раз в час библиотекарь кладёт в память один файл дома
  (docs/*.md, README) — дословно, без выдумок; «почитай» в чате — сейчас;
- **сжатие памяти** — воскресенье 23:00, старые мелочи уезжают в выжимки.

Команды в чате: «вопросы» (что хотела спросить), «ответ 1: ...» (ответить
и запомнить), «подведи день», «почитай».

На панели — карточка «Стремление»: план, вопросы с полем ответа (ответ
уходит сразу в память Марфы), последний дневник, уроки за неделю.

Разум (Круг М): Марфа помнит разговор (сессии в `data\dialog\`, переживают
F5 и рестарт), характер читает из `data\creator_doctrine.json` — поле
`"mood": {"temperature": 0.6, "top_p": 0.8}` меняет живость ответов
без правки кода.

Руками проверить службу: `venv\Scripts\python.exe -m core.drive --tick`
— один такт и честный JSON статуса в консоль.

решает: можно ли живой язык. Это Этап 1 карты восстановления

Как (одна кнопка, вечером, когда дом спит):

2. спросит, какая модель стоит — жми `[4]` (Q4_K_M);
3. два прогона по 15 вопросов, ~10–25 минут: «как есть» и с фиксом

4. соберёт сводку простым языком: **один файл** `logs\battery_report.txt`;
5. положи его в чат архитектору целиком.

Вторая пара — на Q6_K: поменяй модель в `scripts\start_llama_server.bat`
(Q4_K_M → Q6_K), перезапусти мозг, нажми кнопку снова и жми `[6]`.
