## 0. Что уже решено домом (не обсуждается)

1. **Глаза только читают** (Г-1): курсор и клики всегда были территорией
   рук — руки лишь до сих пор не имели мозга.
2. **Каждое действие рук — под надзором стража** (safety/guard.py).
3. **Пиксельная сверка — истина результата** (урок v1.5: состояние
   экрана проверяют пиксели, а не мнение модели).
4. Новое: **супермодель рук найдена и лежит в чулане** —
   UI-TARS-7B-DPO (Q4_K_M + её собственный mmproj-f16).

## 1. Доктрина ролей: четвёртый слуга-разум

| | Мозг (8082) | Глаза (8083) | РУКИ (8084) | Страж |
|---|---|---|---|---|
| Модель | Qwen3-30B-A3B Q4 | Qwen2.5-VL-3B Q4 | UI-TARS-7B-DPO Q4 | код дома |
| Живёт | CPU + ~19 ГБ RAM | VRAM ~3 ГБ | VRAM ~5.4 ГБ **по вызову** | всегда, это код |
| Вопрос | «ЧТО ДЕЛАТЬ?» | «ЧТО и ГДЕ?» | «КАК нажать?» | «МОЖНО ЛИ?» |
| Выход | речь, планы | JSON-дескриптор | действие + координаты | да / НЕТ |
| Никогда | не смотрит пиксели | не трогает мышь | не решает «зачем» | не тормозит без причины |

Следствие: мозг отдаёт задание («открой браузер»), UI-TARS превращает
его в моторику (куда кликнуть, что напечатать), страж одобряет, пиксели
докладывают. **Мозг не жмёт кнопки. Руки не думают. Глаза не трогают.**

## 2. Что за модель (изучение выполнено)

**UI-TARS** — нативный GUI-агент от ByteDance: принимает скриншот и
инструкцию, отвечает ДЕЙСТВИЕМ, как человек. Не «обёртка над GPT-4o с
хитрым промптом», а модель, обученная на следах действий в виртуальных
машинах (Unified Action Modeling + System-2 reasoning + reflect tuning).

Цифры из статьи: OSWorld 24.6 (лучше Claude 3.5 с 22.0), AndroidWorld
46.6 (лучше GPT-4o с 34.5). Для дома важно не «лучше всех», а другое:
**она обучена именно координатно жать по интерфейсам** — то, что мы
собирались собирать из глаз + правил.

Семейство в чулане:
- `UI-TARS-7B-DPO.Q4_K_M.gguf` — тело;
- `UI-TARS-7B-DPO.mmproj-f16.gguf` — ЕЁ визуальный проектор (пара из
  одного семейства; урок llama.cpp: чужой mmproj = «mismatch n_embd»,
  сервер не поднимется);
- `mmproj-model-f16.gguf` (безымянный) — отдельная загадка чулана,
  к рукам отношения не имеет.

Заморозка (честно): репозиторий ByteDance заархивирован в ноябре 2026 —
модель не будет обновляться. Для дома это плюс: наняли — не убежит.

## 3. Формат действий (протокол моторики)

Подтверждено источниками, единое пространство действий:

| Действие | Смысл | Руки дома исполняют |
|---|---|---|
| `click(x, y)` | клик по координатам | pyautogui.click |
| `type('текст')` | напечатать | pyautogui.write (лимит!) |
| `scroll(direction)` | колесо | pyautogui.scroll |
| `hotkey('ctrl+c')` | сочетание клавиш | только по whitelist №19 |
| `wait()` | подождать | пауза цикла |
| `finished()` | задача сделана | отчёт в чат |

Тонкость, честно помеченная: точный диалект координат 7B-DPO
(нормализованная система модели → пиксели экрана) **сверяем на приёмке
Р-0 на живой модели** — здесь ТЗ не выдумывает, а планирует измерить.
Парсер рук строгий: неизвестное действие или мусорные координаты —
честный отказ, а не «лучший гесс».

## 4. Бюджет VRAM — главный урок (арифметика дома)

```
VRAM GTX 1060:              6.0 ГБ
Глаза (работают всегда):    3.0 ГБ   (Q4 2.3 + mmproj 0.7)
UI-TARS Q4 + свой mmproj:   5.4 ГБ
ВМЕСТЕ:                     8.4 ГБ  →  НЕ ВЛЕЗАЮТ
```

Решение: **руки — слуга ПО ВЫЗОВУ** (порт 8084). Пока задачи рук нет —
модель спит на диске, VRAM принадлежит глазам. Пришла команда «кликни»:
слуга поднялся → сделал → лёг. Это зеркально автодоктору: доктор всегда
начеку и лёг, руки спят и встают. Подъём Q4 с NVMe — десятки секунд,
для нечастых задач приемлемо. Будущее: вторая видеокарта = постоянные
руки (в BACKLOG, не в этом ТЗ).

## 5. Цикл задачи (замкнутый, как v1.5, но с моторикой)

«Марфа, кликни Пуск»:

1. агент распознаёт команду рук (мозг молчит — это быстрая команда);
2. слуга рук поднимается на 8084 (если спит);
3. скриншот → UI-TARS: инструкция «нажми Пуск» → `click(x, y)`;
4. парсер: координаты модели → пиксели экрана;
5. **СТРАЖ**: клик в разрешённой зоне? Системные углы, чужие окна,
   «опасные» кнопки — отказ с объяснением;
6. руки жмут (pyautogui — уже в core/hands.py с лимитами);
7. **пиксельная сверка**: экран изменился там, где жали?;
8. слуга ложится (VRAM возвращается глазам);
9. каждый шаг — честная строка в чат и урок эволюционеру.

## 6. Надзор стража (доктрина, №18-20 конкретизированы)

- **Whitelist клавиш** (№19): Esc, Alt+Tab, Enter, стрелки — всё, чего
  нет в списке, отказ. Список — код, не мнение модели.
- **Печать** (№20): только после прямой команды «печатай», лимит длины,
  паттерны секретов (.env, токены) — бан стража на этапе парсинга.
- **Буфер** (№18): только по команде «запиши в буфер», длина ограничена.
- Клик всегда привязан к активному окну: «чужое» окно поверх — стоп.
- Секундный лимит на задачу рук: зависла — честный отказ, не вечный цикл.

## 7. Этапы приёмки (по дисциплине Г-1)

| Этап | Что | Критерий |
|---|---|---|
| **Р-0** | Живой экзамен модели: поднять 8084 с mmproj, «кликни Пуск», сверить координаты UI-TARS с боксом Пуска из дескриптора глаз | координаты в одном боксе |
| **Р-1** | Парсер действий + страж-фильтр (мусор = отказ) | зелёные тесты |
| **Р-2** | Замкнутый цикл с пиксельной проверкой | клик → сверка |
| **Р-3** | Слуга по вызову: start/stop, VRAM-бюджет честен | глаза не падают |
| **Р-4** | №18-20: буфер, клавиши, печать | whitelist работает |

## 8. Чего руки НИКОГДА (проверяется тестами)

- не жмут и не печатают без одобрения стража — ни одного действия;
- не печатают секреты (паттерны .env/токенов — бан на парсинге);
- не исполняют разрушительное (format/del/diskpart — уже в бан-листе
  стража с самого Круга Б);
- не выдают себя за мозг: ответ рук — действие и координаты, не беседа;
- не работают вечно: слуга по вызову, VRAM — общий ресурс дома.
