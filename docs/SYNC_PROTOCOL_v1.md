## Петля: Z440 ⇄ GitHub ⇄ Станция архитектора

> Дата: 17.11.2026 · Статус: действует
> Место в иерархии: под docs/MASTER_TZ.md (уровень 2)
> Назначение: как дом, GitHub и станция архитектора обмениваются кодом и знаниями,
> не нарушая два закона: токены никогда в чат (Ф105) и крупные файлы никогда в git (2.4).

## 1. Три берега

| Берег | Что это | Что хранит |
|---|---|---|
| **Z440** (`C:\Marfa`) | дом Марфы, единственная машина с авторизацией GitHub | весь код + рантайм (модели, venv, логи, data, .env) |
| **GitHub** (`github.com/kernedmd/marfa`, private) | вторые берега: резервная копия истории | только код и документы; рантайм исключён .gitignore |
| **Станция архитектора** (персистентная Linux-песочница Z.ai) | рабочее место архитектора: забор, тесты, правки, память | рабочая копия репозитория + docs/ARCHITECT_LOG.md |

## 2. Петля за один цикл

```
Z440:  scripts\80_sync_github.bat          (одна кнопка Создателя)
  1) импорт incoming\*.bundle от архитектора (если положен)
  2) коммит всего, кроме игнорируемого (+ страховка: файлы >50 МБ убираются)
  3) git push origin main                  → GitHub обновлён
  4) git bundle create outgoing\marfa-*.bundle
Создатель кладёт outgoing\*.bundle в чат архитектору.

Станция: python3 scripts/server_sync.py    (одна команда архитектора)
  1) забор bundle из upload/ → merge в рабочую копию
  2) распаковка zip от Создателя (если есть) → коммит
  3) тесты: compileall всего кода + pytest дома (офлайн)
  4) запись в docs/ARCHITECT_LOG.md        → память архитектора
  5) bundle станции → download/
Архитектор работает (правки, тесты, коммиты) и отправляет bundle Создателю.

Создатель кладёт bundle в C:\Marfa\incoming\ и снова нажимает кнопку. Цикл замкнулся.
```

## 3. Крупные файлы и секреты

- `.gitignore` дома исключает: `models/`, `downloads/`, `*.gguf`, `venv/`, `python311/`,
  `tools/`, `data/`, `logs/`, `.env`, `incoming/`, `outgoing/`, `*.bundle`.
- `80_sync_github.bat` дописывает недостающие строки в `.gitignore` сам и убирает
  из коммита любые файлы больше 50 МБ (страховка поверх .gitignore).
- Токены/ключи живут только на Z440 (`SSH-ключ` или разовый PAT — docs/GITHUB_PUSH.md).
  В чат, в логи, в bundle они не попадают никогда: станция работает БЕЗ ключей —
  пуш делает только Создатель со своей машины.

## 4. Почему bundle, а не прямой доступ станции к GitHub

Приватный репозиторий требует авторизации. Единственный способ дать станции доступ —
передать токен, а это запрещено Ф105 и гигиеной 2.4 (токен в чат — никогда).
Bundle решает задачу без секретов: он содержит всю git-историю, проверяется
(`git bundle verify`), мерджится как обычный remote и едет через чат как обычный файл.

## 5. Память архитектора — docs/ARCHITECT_LOG.md

Журнал живёт в репозитории и путешествует по всем трём берегам. Каждая синхронизация
дописывает запись: дата, HEAD, что забрано, результаты тестов. Контекст ИИ-сессий
теряется — файлы станции остаются; ARCHITECT_LOG — механизм «помнить» для архитектора.
Правило записи: факты и цифры, без воды; каждая запись датирована.

## 6. Первый запуск (разовый, 17.11.2026)

1. Распаковать `marfa_architect_pack_1711.zip` поверх `C:\Marfa` (добавятся docs/ и scripts/).
2. `scripts\80_sync_github.bat` — первый коммит канона v10.0-pre + пуш + bundle.
3. Bundle из `outgoing\` — в чат архитектору: станция получит код дома, и pytest
   дома заработает на станции (сейчас там только канон и скрипты, тестов дома нет).
4. Дальше — по петле раздела 2.

## 7. Открытая возможность (на резолюцию Создателя)

«Пульс станции»: ежедневное срабатывание архитектора по расписанию (проверка станции,
прогон тестов, короткий доклад Создателю). Включается только явной резолюцией —
вопрос №6 к MASTER_TZ.
