## 1. Почему v2 — возвращение к дому

ТЗ Рук v1 наняло UI-TARS-7B-DPO четвёртым слугой-разумом (порт 8084)
с церемонией «слуга по вызову»: глаза присели → руки поднялись
(десятки секунд с NVMe) → сделали → руки легли → глаза вернулись
доктором (ещё десятки секунд). Живой прогон станции 22.11 показал
цену этой конструкции:

- **камера слепнет**: пока руки на посту, сенсор зрения (8083) мёртв —
  «посмотри на меня» и «проверь камеру» стоят в очереди;
- **десятки секунд на каждую смену хозяина VRAM** — дважды на задачу;
- **«посмотри на меня» ушло рукам** (через ui_action) — VRAM-танец
  впустую и клик в никуда;
- **7B-модель со своим диалектом** (start_box, content=, key='ctrl c') —
  отдельный парсер, отдельные промпты, отдельные болезни.

Отклонение от мастер-ТЗ (канон, 17.11), которое вскрыл Создатель:

| Закон мастер-ТЗ | Что сделала v1 |
|---|---|
| §4: VRAM 6 ГБ — хозяин ГОЛА; смена хозяина только по расписанию | руки гасили глаза при каждой задаче |
| §8 + Р-4: Qwen2.5-VL-3B выбрана, ПОТОМУ ЧТО возвращает текст и координаты — «кнопка "Отправить": X 450, Y 600» | наняли вторую VLM-модель делать то, что уже умеет первая |
| §10.2: клик — только по валидированному центру bbox | клик по координатам UI-TARS, диалект которых ещё измерять надо |
| §10.3: элементы с confidence < 0.6 — НЕИЗВЕСТНЫЕ | уверенность UI-TARS не проверялась вовсе |

**Решение Создателя (22.11):** вернуть дом к доктрине. У дома ОДНО
зрение — глаза 8083. Рукам своя модель не нужна: они — исполнитель
координат глаз. UI-TARS отправляется в чулан; порт 8084 свободен.

## 2. Доктрина единого зрения

Роли не смешиваются (мастер-ТЗ §3), у каждой — свой вопрос:

| | Глаза (зрительная кора) | Руки (моторная кора) |
|---|---|---|
| Кто | Qwen2.5-VL-3B + mmproj, порт 8083, VRAM | код дома (`core/motor.py`) |
| Вопрос | «ЧТО на экране и ГДЕ оно?» | «КУДА жать?» — берёт ответ глаз |
| Даёт | дескриптор: элементы с ПРОЧИТАННЫМ текстом, bbox, confidence | клик по центру bbox, печать, клавиши, прокрутка |
| Никогда | не решает, не кликает | не смотрит, не думает, не выдумывает координаты |

Ключевое следствие: **координаты рукам дают только глаза**. Мозг не
называет координаты никогда (он их не знает); руки не спрашивают
никакую модель «куда жать» — они берут валидированный bbox из
дескриптора и жмут в его центр (мастер-ТЗ §10.2).

## 3. Архитектура v2

```
Создатель / мозг (ui_action)
        │  задание словами: «нажми Пуск»
        ▼
   core/motor.run(task)
        │  1) разбор глагола (§4)
        │  2) глаза.describe_with_sizes()  ← ОДИН взгляд, сервер 8083 ЖИВ
        │  3) find_element: надпись ↔ текст задания, confidence ≥ 0.6
        │  4) click_point: центр bbox × масштаб кадра → пиксели экрана
        │  5) СТРАЖ (§5): границы, whitelist, канарейки
        ▼
   сухой режим: «кликнула бы в (x, y)» ── кнопка 91 не нажата
   моторика: pyautogui.click(x, y) → новый снимок → пиксельная сверка
```

- Сервер зрения **не гаснет никогда**: руки не поднимают и не
  укладывают серверов. Ответ рук = один взгляд глаз (~9 с на GTX 1060),
  а не перезапуск модели (десятки секунд × 2).
- **VRAM не танцует**: хозяин 6 ГБ — глаза (мастер-ТЗ §4). Единственный
  оставшийся заёмщик VRAM — кодер-слуга (8085, `core/vram.py` +
  `core/repair.py`): он текстовый и тяжёлый, его танец — отдельная
  церемония заёма.
- **DPI-честность** (§6): перед движением мыши процесс становится
  per-monitor DPI aware — pyautogui говорит в физических пикселях.

## 4. Протокол задания (глаголы)

Задание — русская фраза с глаголом; глагол выбирает действие:

| Глаголы | Действие | Куда |
|---|---|---|
| нажми / клини / щёлкни / открой / запусти / тыкни `<надпись>` | клик по элементу с этой надписью | центр bbox элемента |
| напечатай / набери / введи / напиши `<текст>` | печать в активное поле | латиница ≤ 120 символов |
| клавиши / сочетание / горячая `<ctrl+c>`; «нажми enter» | сочетание из whitelist | №19 |
| прокрути / листай `<вверх\|вниз>` | прокрутка | ±300 |

Сверка текстов — честная, в три шага: точное совпадение → надпись
внутри цели («Пуск» ⊂ «нажми кнопку Пуска») → цель внутри надписи
(«блокнот» ⊂ «Блокнот — Безымянный»). Регистр и «ё» нормализуются,
слова-указатели («кнопку», «ссылку», «поле») снимаются.

Честные отказы (не выдумки):

- **не вижу** — «глаза не видят на экране "X". Глаза читают: …» —
  Создатель видит, что есть на экране, и может сказать «посмотри»;
- **не рискнула** — похожий элемент найден, но confidence < 0.6
  (мастер-ТЗ §10.3: неуверенное — НЕИЗВЕСТНОЕ);
- **глаза не отвечают** — сервер зрения мёртв; руки НЕ поднимают
  свой сервер и не рестартуют чужой (лечение зрения — «доктор»).

Составные задания («открой Блокнот и напечатай привет») — работа
мозга: он декомпозирует и зовёт ui_action несколько раз.

## 5. СТРАЖ моторики (без изменений из v1)

- клик — только в пределах экрана (плюс инвариант: валидированный
  bbox + масштаб никогда не выводят точку за экран — клип в
  `scale_point` и 200-случайный тест);
- печать: ≤ 120 символов, латиница (кириллица — честно «не умею»,
  Круг Р-4: буфер обмена впереди), канарейки/токены банятся;
- клавиши: только whitelist №19 (esc, enter, tab, alt+tab, стрелки,
  ctrl+c/v/a, space, backspace); alt+f4 — никогда;
- каждое действие — вердикт стража в лог + строка в
  `logs\hands_log.jsonl` (правило 6.6: логи — истина).

## 6. Замкнутый цикл и DPI (мастер-ТЗ §10.2, §10.4)

- после моторного клика — новый снимок и **пиксельная сверка**
  (доля изменившихся пикселей в области бокса; > 30 по яркости —
  изменение): «у клика экран изменился на N% кадра»;
- экран почти не изменился — честный доклад: «возможно, клик не
  сработал; скажи "посмотри", проверю глазами»;
- DPI-awareness: `SetProcessDpiAwareness(2)` перед первым движением
  мыши (повторный вызов безвреден; вне Windows — молчит).

## 7. Экзамен Р-0 v2 — цепочка глаза→руки

Команда «руки, экзамен». Глаза дают бокс Пуска из дескриптора, руки
считают центр и масштаб — и показывают всю арифметику Создателю:

- **сухой режим** (по умолчанию): «кликнула бы в (x, y)» + приглашение
  включить моторику кнопкой 91 и повторить;
- **моторика включена**: настоящий клик → пиксельная сверка всего
  кадра → вердикт:
  - изменилось > 1% — «ЦЕПОЧКА РАБОТАЕТ: глаза навели точно, руки
    нажали верно»;
  - не изменилось — «координаты глаз могут врать; НЕ доверяй моторике
    вслепую, сообщи архитектору цифры»;
  - уборка за экзаменом: Esc (из whitelist) закрывает меню Пуска.

Диалект координат больше не измеряется — его нет: bbox глаз живёт в
пикселях отправленного кадра (валидатор глаз v3 гарантирует), масштаб
кадр→экран считает код. `data\hands_dialect.json` больше не нужен.
