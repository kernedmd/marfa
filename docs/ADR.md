# ADR — архитектурные решения Марфы

Журнал решений, названных в ТЗ v9.3. Полные ADR-файлы у Ильи на Z440; здесь — суть,
чтобы код в репозитории не расходился с мотивировкой.

## ADR-002 — СТРОГИЙ JSON tool calling (core/brain.py)

Мозг обязан вернуть либо `{"answer": "..."}`, либо `{"action": {"tool": ..., "args": {...}}}`.
Парсинг **только** `json.loads` — никаких регексов и «спасения» обрезанного JSON.
Брак → повтор с укором → fallback. Мотивация: регексы по ответам LLM — главный
источник тихих поломок старого каркаса (ТЗ Раздел 7 выбрасывает их).

## ADR-003 — ОДИН фильтр СТРАЖ (safety/guard.py)

Пять врат снаружи заменены одним фильтром с уровнями LOW/MEDIUM/HIGH/CRITICAL/BANNED.
Защита ОС, канарейки, hash-chain лог, скан prompt injection — внутри одного модуля.
Аудит доступа пишется независимо от вердикта (проверяет Ф81).

## ADR-004 — Pascal-режим QLoRA (growth/, скрипт 04)

GTX 1060 (CC 6.1) не поддерживает LLM.int8 — нужен bitsandbytes NF4 +
`paged_adamw_8bit`, batch 1 + grad-accum 16 + checkpointing, дедлайн 06:30 в колбэке.
LLM.int8 запрещён. QLoRA — только ночью 04:30-06:30 (правило 0.4), днём GPU свободна.

## ADR-005 — Контекст 4096 навсегда (core/config.py, core/context.py)

Контекст 4096 — закон доктрины независимо от объёма RAM: промпт 3072
(внутри — сжатая история Ф53 не более 1000) + генерация 768, запас 256.
Сборка промпта — только через core/context.py с гарантией бюджета.

## ADR-006 — ChromaDB с прозрачным JSON-фоллбэком (core/memory.py)

Память обязана работать всегда: если chromadb не установлен или упал —
тот же интерфейс на JSON-файле (`data/memory/memory.json`, атомарная перезапись).
Агент не знает, на каком бэкенде работает.

## ADR-009 — Студент Qwen2.5-3B-Instruct (скрипт 04)

У семейства Qwen3 плотной 3B нет — QLoRA-студент: **Qwen2.5-3B-Instruct**
(≈6 ГБ safetensors: два шарда model-0000X-of-00002 + model.safetensors.index.json;
закачка — scripts/download_student.py, SHA-256 шардов сверяются жёстко, урок 12.11.2026).
7B и 3B в диалоге не участвуют (ТЗ 2.1): диалоговый мозг — только 30B MoE на CPU.
## ADR-010 — Нативные зонды только через Invoke-ExeProbe/Invoke-Logged (все скрипты установки)

Любая строка, написанная нативной командой в stderr, при `$ErrorActionPreference = "Stop"`
(_common.ps1) и перенаправлении `2>&1`/`2>$null` становится терминающей ошибкой
(Windows PowerShell 5.1). Проявилось 12.11.2026 на шаге 5 аудита: llama-server печатает
баннер версии в stderr — аудит убил сам себя строкой «КРИТ: version: 0.9.0-dev
(build 12292, ...)». Правило: нативные вызовы в скриптах установки — только через
Invoke-ExeProbe/Invoke-Logged (System.Diagnostics.Process, без 2>&1, таймаут
обязателен). Исключение — curl в Get-RemoteFile: без перенаправления, прогресс виден
в консоли. Проверки, где git может отсутствовать (`.env не в git`), мягкие: нет git /
не репозиторий = пропуск с пометкой, не провал.

## ADR-011 — Код дома собирается на Python 3.11: никаких конструкций PEP 701 в f-строках

В выражении f-string `{...}` нельзя «\» и кавычку-разделитель строки: это разрешили
только в Python 3.12 (PEP 701). Проявилось 13.11.2026: web/app.py печатал подсказку
«см. scripts\start_llama_server.bat» прямо в f-выражении — на 3.11 машины файл падал
SyntaxError ещё при импорте («1 error during collection» в pytest), а песочница
разработчика на 3.12 молчала: 125 тестов зелёные, а конвейер у пользователя стоит.
Правила: (1) любой текст с «\» вычисляется ДО шаблона — в f-выражение входит только
имя переменной; (2) в verify.ps1 ПЕРЕД pytest стоит проверка «selftest compile»:
compileall собирает ВСЕ наши .py тем самым python.exe из venv, что и тесты (на машине
это честный 3.11) — несовместимость всплывает с именем файла и строкой за секунды,
а не после минут угадывания по хвосту вывода.
